# 2차 MVP 계획

> 상태: 개정판 · 2026-09-04 (8/21 초안 → 8/28 전략 전환 → 9/1 심사 결과 반영 → 9/3 표면 재분배·알림 축·탭 구조 확정 → 9/4 기능 확장·8시간 대응 스택 정리)

## 목표

**리텐션을 만든다.** 잠금화면에서 매일 보이는 가치를 늘려 습관을 만들고, 서버 기반 수익화(동기화·push)는 리텐션 데이터가 이를 정당화할 때 3차로 미룬다. 서버가 필요 없는 로컬 Pro는 2차 범위에 포함하되(v1.3), 2차의 성공 지표는 어디까지나 리텐션이고 수익은 "전환율 데이터 수집"으로 프레이밍한다.

## 왜 전략을 바꿨나 (구독 우선 → 리텐션 우선)

8/21 초안은 서버 구축 + Sign in with Apple + 동기화 + StoreKit 구독을 2차 범위로 잡았다. 8/28 검토에서 다음 이유로 뒤집었다.

1. **서버 운영 비용이 수익보다 먼저 발생한다.** 구독자 0명이어도 APNs 스케줄러와 DB는 계속 돈다.
2. **동기화는 1차 MVP 전체보다 난이도가 높다.** 오프라인 편집·충돌·부분 실패까지 다루면 범위가 폭발한다.
3. **팔기 전에 매일 쓰는 습관이 먼저다.** 리텐션 없는 앱에 페이월을 붙이면 이탈만 만든다.
4. **Meteor 선례: 서버 없이도 구독이 성립한다.** Meteor(월 $3.99 / 연 $24.99, ★4.6/136리뷰)는 로컬 기능 게이팅만으로 수익화했다. 서버는 구독의 전제조건이 아니다.

8/21 초안의 서버·계정·동기화·push-to-start 설계는 폐기가 아니라 **3차 MVP의 설계도**로 이월한다 (문서 하단 참조).

## 핵심 설계: 표면 역할 재분배 (9/3)

위젯과 LA의 진짜 차이는 **수명**이다. LA는 8시간이면 갱신이 멈추고, 위젯은 사라지지 않는다.
각 메모 타입을 수명에 맞는 표면에 배치한다.

| 타입 | 표면 | 보조 알림 | 근거 |
|---|---|---|---|
| 디데이 | 위젯 | D-day 당일 알림 (선택) | 장기 지속형 — LA 8시간 수명과 미스매치 |
| 달성률 | 위젯 | — | 며칠 단위 진행 (홈화면 위젯은 iOS 17+ 인터랙티브 버튼으로 조작 검토) |
| 일반 텍스트 | LA | 만료 예고 → 탭하면 재게시 | 상시성이 약점이나 선례 다수 (심사 조사 참조) |
| 체크리스트 | LA (토글 유지) | 만료 예고 | 하루 단위 소화, 상호작용이 LA 강점 |
| 카운트다운 | LA (`Text(timerInterval:)`) | 완료 시각 알림 | 시작·끝이 있는 LA 정석 사용례, 대부분 8시간 내 종료 |

효과:

- 8시간 제약이 아픈 타입(디데이·달성률)이 위젯으로 빠져 **"종일 LA"의 필요성 자체가 줄어든다** → v1.2 심사 리스크 하락
- 기존 위험 항목이던 **위젯·LA 역할 중복이 구조적으로 해소**된다 (같은 디데이가 두 표면에 뜨는 상황이 없어짐)

### 탭 구조: "메모 / 위젯"

홈 단일 리스트(+DisplayFilter)를 TabView 2탭으로 재편한다.

- **메모 탭**: 일반·체크리스트·카운트다운. 표시 중/만료 상태, 재게시, 만료 예고 알림 등 LA 수명 관리 UX는 이 탭에만 존재
- **위젯 탭**: 디데이·달성률. 표시 상태 개념 없음. 위젯 항목 선택·정렬 + 위젯 추가 가이드 (위젯은 앱이 대신 설치할 수 없어 사용자 안내 필수)
- 이름 결정 경위: "오늘/늘", "지금/항상", "잠금화면/위젯" 비교. "잠금화면"은 잠금화면 위젯과 자기모순("잠금화면 위젯은 위젯 탭에 있음")이 생겨 제외. **"메모/위젯"이 구체성과 무충돌을 동시 충족**
- 마이그레이션: `renderType`으로 결정적 분류 — 데이터 변경 없음. 단 v1 사용자의 디데이가 위젯 탭으로 이동하므로 업데이트 후 최초 실행 1회 안내 필요
- 작성 플로우: 현재 탭에 맞는 타입만 기본 제시 (메모 탭 + → 일반/체크리스트/카운트다운)

## 8시간 문제 — 대응 스택 (9/4)

**LA는 시작 후 8시간이면 시스템이 강제 종료하고, 이 한도는 앱이 늘릴 수 없다.**
이것이 이 제품의 최대 제약이며, 단일 해법이 아니라 **스택**으로 대응한다.
동일 카테고리 앱 전부가 같은 제약을 받으므로, 이 스택의 완성도가 곧 경쟁력이다.

| 층 | 대응 | 사용자 부담 | 시점 |
|---|---|---|---|
| 0 | **노출 축소**: 8시간이 아픈 타입(디데이·달성률)을 위젯으로 이관 — 문제 자체를 회피 | 없음 | v1.1 |
| 1 | **만료 예고 알림**: 8시간 시점 알림 → 탭 → 앱 진입 → 자동 재게시 | 탭 1회 | v1.2 |
| 2 | **앱 진입 시 자동 재게시**: 언제든 앱을 열면 만료 LA 복원 (opt-in) | 앱 열기 | v1.2 |
| 3 | **잠금화면 컨트롤 버튼** (iOS 18+): 원터치 재게시 | 버튼 1회 | v1.2 |
| 4 | **Shortcuts 정시 자동화**: 개인 자동화(매일 N시) + `LiveActivityIntent`(17.2+) → 이후 매일 완전 자동 게시. 앱 내 설정 가이드 제공 | 최초 1회 설정 | v1.2 |
| 5 | **서버 push-to-start 체이닝**: 8시간 주기 원격 재생성 → 설정 0, 사실상 무기한 + 정각 제거 | 없음 | 2.5차 (Pro) |

로컬(0~4층)의 한계: "설정 0 + 개입 0 + 무기한"은 불가능하다. 그 마지막 조각(5층)이 서버의 존재 이유이자 Pro 프리미엄의 근거다.

기술 참고:
- LA 시작 경로는 포그라운드 / push-to-start(서버) / `LiveActivityIntent`(Shortcuts) 셋뿐. 알림·백그라운드 태스크로는 시작 불가
- 8시간 정각 제거도 로컬 보장 불가 (`.after` 예약은 4시간 한도 + 호출 즉시 갱신 동결) → `staleDate`로 만료 표시 전환 + 진입 시 정리
- 종료 후 잠금화면 잔류(최대 4시간)는 "죽은 카드" — 비상호작용 타입은 정보 가치가 남으므로 타입별 정리 정책 검토

## 범위

### 1. 위젯 + 탭 재편 (WidgetKit) — 리텐션 축 (v1.1)

- 잠금화면 위젯: inline / circular / rectangular — 디데이, 진행바
- 홈화면 위젯: small / medium — 디데이·달성률 목록
- 갱신 예산 문제 없음: 디데이는 하루 1회 갱신, 카운트다운류는 `Text(date, style:)`로 시스템이 실시간 렌더링
- 탭 구조 개편("메모/위젯") + 디데이·달성률 타입 이관 포함
- 서버 불필요, 심사 리스크 낮음

### 2. LA 수명 관리 + 알림 축 + 진입 마찰 제거 (v1.2)

**알림 (UNUserNotificationCenter, 서버 불필요):**

- **만료 예고**: LA 시작 시 8시간 시점(직전) 로컬 알림 예약 → 탭 → 자동 재게시
- **카운트다운 완료 알림**: 목표 시각에 예약. LA가 이미 내려갔어도 완료를 놓치지 않음
- **반복 알림**: 매일 / 매주 X요일 / 주중(월–금, 트리거 5개) / 주말(트리거 2개). 반복 알림 → 탭 → 오늘의 메모 재게시가 습관 루프의 시작점
- **앱당 로컬 알림 64개 한도** → 포그라운드 진입 시 예약 재정리(만료분 제거 + 재예약) 로직 필수
- 알림은 설정에서 유형별로 끌 수 있게 한다 (4.5.3 스팸 금지 + 성가심 방지)

**재게시·자동 게시 (8시간 스택 1~4층 구현):**

- 앱 포그라운드 진입 시 만료 LA 자동 재게시 (opt-in 토글, 기본값 미결) — `cleanupExpired`의 "내리기"를 "내리고 다시 띄우기"로 확장
- **정시 자동 게시**: `LiveActivityIntent` 제공 + Shortcuts 개인 자동화(시간 트리거, 확인 없이 실행) 설정 가이드. 1회 설정 후 매일 완전 자동
- 잠금화면 컨트롤·컨트롤 센터 버튼 (iOS 18+, `#available`): 원터치 재게시·빠른 메모

**입력 마찰 제거:**

- **App Shortcuts (시리)**: "시리야, 메모 띄워줘" / "주차 위치 F3 43" — 설정 없이 자동 노출
- **템플릿/프리셋**: 작성 화면에 프리셋 제공 — 외출 체크리스트, 주차 위치, 오늘의 의도, D-day 세트(디데이 위젯 + 오늘 체크리스트 동시 생성)
- 주차 자동화 가이드: 블루투스 연결 해제 트리거(카플레이 불필요) / NFC 태그 → 인텐트 실행. 실내 층·구역은 자동 캡처 불가 → 감지는 자동, 라벨은 시리·수기 3초 (사진 OCR은 이후 카드)

**표시 커스터마이징 (무료):**

- **글자 크기 조절**: S/M/L + Dynamic Type 존중. `ContentState.font` 인프라 기존재. **접근성 항목이므로 Pro 게이팅 금지**

**심사 방어 (5중 유지 + 9/3 조사 반영):**

| 방어층 | 내용 |
|---|---|
| ① 베이스라인 | v1.0 승인 확정, 기능 지적 0건 + 동일 컨셉 생존 앱 다수 (아래 조사) |
| ② 독립 릴리즈 | v1.2 단독 릴리즈 → 리젝 시 이 기능만 롤백 |
| ③ 설계로 이의 제거 | opt-in(기본 off), 사용자가 지우면 재게시 안 함, 심사 노트에 "사용자 생성 콘텐츠만 표시, 마케팅 용도 없음" 명시 |
| ④ 폴백 경로 | Shortcuts + `LiveActivityIntent` (심사 대상 아님) |
| ⑤ 사전 검증 | TestFlight 베타 실사용 검증 |

9/3 심사 사례 조사 결과:

- 공식 가이드라인의 LA 언급은 **4.5.3 하나** — 스팸·피싱·원치 않는 메시지 금지 (2026 개정에서 추가). 지속 시간·용도 제한은 가이드라인에 없음 (HIG 권고 수준)
- "지속형 LA라서 리젝" 공개 사례는 영어·한국어 커뮤니티에서 미발견. 발견된 LA 포함 앱 리젝은 4.2(최소 기능성) 등 다른 사유
- 동일 컨셉 생존 앱: Meteor, **LockNote**(2025 출시, "keep it permanent" 옵션 + Pro 월 $4.99/연 $39.99), ScreenPin, Notepad Live
- 단, 리젝된 개발자는 글을 안 쓰는 생존 편향 있음 → 사례 미발견 ≠ 리스크 없음, 5중 방어 유지

### 3. 로컬 Pro — Meteor 모델 (v1.3)

StoreKit 2 로컬 구독. 게이팅 축 3개 — 모두 신규 가치라 "이미 제공하던 기능은 잠그지 않는다" 원칙에 부합.

| 축 | 무료 | Pro |
|---|---|---|
| 동시 LA 메모 수 | 1개 | 다중 |
| 반복 알림 | 단발만 | 매일·매주·주중·주말 |
| LA 디자인 테마 | 기본 스타일 | 색상 팩·카드 스타일 (컴팩트/스탠다드 등) |

- 가격 벤치마크: Meteor 월 $3.99 / 연 $24.99, LockNote 월 $4.99 / 연 $39.99
- 서버 비용 0 → 손익분기 개념 없음. 수익 자체보다 **전환율 데이터 수집**이 목적 (2.5차·3차 서버 투자 판단 근거)
- 글자 크기는 접근성이므로 무료 유지 (게이팅 금지)

## 포지셔닝 (초안)

한 줄: **"잠금화면을 작전상황판으로."**

- **의도 개입** (브랜드 서사): 모든 딴짓은 잠금 해제에서 시작된다. 폰을 여는 순간 하려던 일이 먼저 보이게 — 차단(Opal·one sec류) 아닌 상기. 반복 알림 + LA 조합으로 구현
- **작전상황판** (구조적 차별화): 위젯(장기 목표: D-day·달성률) + LA(오늘의 실행: 체크리스트) 동시 표시 — 경쟁 앱은 어느 한쪽만 함. 표면 재분배 설계의 부산물이자 고유 그림
- **순간 메모** (입소문 유틸리티): 주차 위치·호텔 방·게이트 — 8시간 수명이 정확히 맞는 용도. 시리·자동화·템플릿으로 등록 마찰 제거가 성립 조건
- 스토어 문구·스크린샷·온보딩을 도구 설명("잠금화면 메모")이 아닌 장면 중심으로 재작성

## 범위에서 제외

**→ v1.4 (서버 불필요, 독립 릴리즈):**

- CloudKit 동기화·백업 (SwiftData+CloudKit): 개발자 서버 0원으로 기기 간 동기화·데이터 보존. "개발자 서버 전송 없음" 스탠스 유지 가능(사용자 iCloud 프라이빗 DB). 모델 제약(전 프로퍼티 옵셔널 등) 마이그레이션 검토 필요

**→ 2.5차 (미니 서버 — 스케줄러 + APNs 토큰 저장소, 서버리스 월 $0~5):**

- **예약 게시**: 매일 아침 서버가 push-to-start로 LA 자동 생성 — 설정 0, 습관 루프의 완전판. Pro 프리미엄 후보
- push-to-start 체이닝 (무기한 LA, 8시간 스택 5층) + APNs `end` 푸시 정각 제거
- 대가: 메모 내용이 APNs 페이로드로 전송됨 → "서버 전송 데이터 없음" 스토어 문구 수정 필요. 리텐션·Pro 전환 신호 확인 후 착수

**→ 3차 MVP (풀 서버):**

- NestJS 서버, Sign in with Apple 계정 체계
- 기기 간 실시간 동기화 (충돌 해결 정책 포함) — CloudKit로 충분하면 축소 가능
- 공유 체크리스트 (서버 비용 회수 기능)

**→ 별도 카드 (시점 미정):**

- AlarmKit 알람 모드 (iOS 26+): 무음·집중 모드를 관통하는 진짜 알람. UX 기대치(스누즈·사운드)가 달라 분리. AlarmKit 카운트다운이 LA 프레젠테이션을 쓰므로 접점 있음
- 주차 기둥 사진 → 온디바이스 OCR(Vision) 라벨 추출
- Share Extension (문자·카톡의 예약정보 → 메모 생성)
- 반복 노출 암기 타입 (위젯 타임라인으로 영단어 등 회전 표시)

## 위험

**해소됨 (9/3):** v1.0 심사 미완(→ 승인 확정), 위젯·LA 역할 중복(→ 표면 재분배로 구조 해소).

**8시간 한도 — 최대 제약 (9/4 인식).** 로컬만으로는 "설정 0·개입 0·무기한"이 불가능하다. 대응 스택(전용 섹션)으로 체감을 낮추되, 완전 해소는 2.5차 서버부터다. v1.2 출시 후 "메모가 사라져요" 류 리뷰·문의 빈도를 스택 유효성의 지표로 삼는다.

**로컬 알림 64개 한도.** 주중 반복은 메모당 5슬롯 — 반복 알림 메모가 10여 개면 한도 도달. 예약 재정리 로직과 상한 UX 없이는 조용히 알림이 누락된다.

**마이그레이션 혼동.** v1 사용자의 디데이 메모가 위젯 탭으로 이동한다. 최초 실행 1회 안내가 없으면 "메모가 사라졌다"는 리뷰가 달린다.

**알림 성가심.** 만료 예고가 매일 반복되면 평점 리스크. 기본값은 보수적으로, 끄기는 쉽게.

**v1.2 범위 비대화.** 알림 축 + 시리 + 컨트롤 + 템플릿 + 글자 크기가 한 릴리즈에 몰렸다. 지연 시 분리 순서: 템플릿 → 컨트롤 → 글자 크기 순으로 뒤로 뺀다 (알림·재게시가 코어).

**심사는 리스크 제로가 아니다.** 사례 미발견은 생존 편향일 수 있다. 5중 방어는 리젝 확률을 낮추는 게 아니라 **리젝을 감당 가능하게** 만드는 구조다. 리젝 시 폴백(Shortcuts)으로 전환하고 로드맵은 계속 간다.
